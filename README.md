# 中文文档问答 Agent

基于 DuReader Retrieval 语料的中文文档问答 Agent：手写 ReAct 循环、本地向量检索、双层任务编排与确定性准入控制。

**冻结留出集 30 题验收**：可判断题目答案正确率 **80%**（16/20；另有 10 题因证据不足未计入）· 引用完全支持率 **67.3%** · 受控无依据题 **10/10** 全部正确拒绝、未编造

> 个人项目，用于完整走通「检索 → 工具调用 → 评测 → 准入控制」这条链路。
> 非生产系统；引用只表明被引材料支持该表述，不代表现实事实已被核实。

---

## 技术要点

| 层 | 实现 |
| --- | --- |
| **Agent 循环** | 自研 ReAct，不依赖 LangChain 等编排框架：模型 → 工具 → 结果回填 → 再问。含步数上限、工具超时与有限重试、结构化错误回填、重复调用保护；工具在独立子进程执行并按进程组回收 |
| **检索** | DuReader Retrieval 全量约 **809 万段落**；BGE 中文向量 + FAISS 分片精确扫描 + reranker 重排，返回 top-5；分片扫描避免全量向量常驻内存 |
| **双层编排** | 外层把目标拆成问题清单并逐题派工，内层在题目边界执行与汇总；外层与内层是不同模型调用，综合回答复用已有结果、不新增检索 |
| **准入控制** | 确定性闸门，**不经过模型**；`off / observe / auto` 三态渐进；`explicit / inferred` 二元强度；策略版本与恢复前重校验；消息文本无法改变权限 |
| **服务** | FastAPI + SSE 流式；协作式取消；`/healthz` 轻量健康检查；单进程单任务并发控制；可配置任务期限 |
| **协议** | MCP stdio 暴露 `search_docs` / `read_passage` |
| **测试** | 166 项自动测试（多为模拟模型与工具，非准确率测试） |

## 评测

冻结留出集 30 题，2026-11-11 运行，DeepSeek `deepseek-flash`，FAISS 检索后端，最大步数 8。题集按预定抽样规则生成，抽取后未参与调参。

| 指标 | 结果 | 说明 |
| --- | --- | --- |
| 答案正确 / 可判断题目 | **16/20 = 80.00%** | 仅排除证据不足的题 |
| 答案正确 / 全部题目 | **16/30 = 53.33%** | 10 道「无法判断」保留在分母 |
| 引用完全支持（项级） | **142/211 = 67.30%** | 逐条核对引用材料是否支持该表述 |
| 全部引用均完全支持的题 | 6/29 = 20.69% | 题级严格口径 |
| 无依据题正确处理 | **10/10 = 100%** | 10 道合成受控情景 |
| 首次检索 Hit@3 | 20/30 = 66.67% | 检索命中率，**不是**答案正确率 |
| 平均耗时 / P95 | 47.58 秒 / 74.29 秒 | 含模型与工具执行 |

**口径说明**：Hit@k 是检索命中率；开发集与留出集数字不可合并表述；「无法判断」既不算对也不算错，展示 80% 时必须同时说明它来自 20 道可判断题。

## 架构

```
问题 ──> Agent 循环（自研 ReAct）
                │
      ┌─────────┼─────────┐
      ▼         ▼         ▼
  本地检索   网页搜索/抓取   计算
(BGE+FAISS)              (子进程)

双层实验：
事件 ──> 确定性准入闸门 ──> 外层研判/规划 ──> 工单 ──> 内层逐题执行 ──> 综合回答
          (不经过模型)      (模型)                  (复用前序证据)
```

## 运行

需要 Python 3.11+。语料与索引体积较大，不在仓库内分发，需自行下载构建。

```bash
python -m venv .venv
.venv/bin/pip install -r requirements.txt      # Windows: .venv\Scripts\pip.exe
cp .env.example .env                           # 填入 LLM_BASE_URL / LLM_API_KEY / LLM_MODEL_ID
uvicorn app.server:app --host 127.0.0.1 --port 8000
```

打开 `http://127.0.0.1:8000/`（普通助手）、`/super`（双层实验）、`/healthz`（健康检查）。
接口兼容任意 OpenAI 风格端点。索引构建步骤见 `eval/`。

## 已知限制

- **语料质量**：DuReader 含旧网页、论坛问答与营销内容。检索到并忠实转述，不等于事实正确；医疗、法规、价格等时效性内容不可依赖。
- **答案正确性**：留出集仍有 10/30 无法判断；模型可能漏检、错挂引用或未按篇幅作答。
- **高风险识别薄弱**：仅依赖有限关键词，**不可用于医疗、婴幼儿照护、燃气等高风险场景**。
- **引用归属**：存在明确错挂，以及「引用共享来源但该句实际未引用」的情况。
- **非多用户系统**：单进程单任务锁，忙时返回 409；模拟身份不是登录认证，不提供权限隔离。
- **取消是协作式的**：在模型/工具调用边界检查，不保证立即中断已发出的同步调用。
- **不可开箱即用**：语料与索引需自行构建，跨机器复现需要磁盘与时间。

## 关于本项目

从零手写 Agent 循环，不用 LangChain 等编排框架，目的是把模型之外的脚手架——工具协议、上下文管理、错误回填、准入判定、评测口径——自己实现一遍。准入控制部分参考了 DeepSeek 官方 super-agent 原型（MIT）的公开设计，用 Python 重新实现。
